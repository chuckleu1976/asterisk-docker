================================================================================
  asterisk-docker Ubuntu x86 setup guide
================================================================================

This file is a clean-machine installation guide for the asterisk-docker SMS
and VoLTE/VoWiFi gateway stack on Ubuntu 24.04 or 26.04 x86_64.

It assumes USB SIM readers and local SIM cards. After the packages in
sections 2 through 9 are in place, ./setup-x86.sh builds the images from
the Dockerfiles in this repository and starts one container per inserted
SIM. Remote SIM mode is described in section 6; do not use it for USB
readers on this machine.

================================================================================
  1) Prerequisites
================================================================================

- Ubuntu 24.04 or 26.04 LTS x86_64
- A machine with USB ports and one or more USB SIM card readers
- At least one SIM card with VoLTE/VoWiFi support
- Internet access for Docker images and package installation
- A Telegram bot token and chat ID if you want SMS notifications
- Optional but recommended: a static LAN IP address for the host

================================================================================
  2) Install base packages
================================================================================

Run these commands as root or with sudo:

  sudo apt update
  sudo apt install -y ca-certificates curl gnupg lsb-release git \
      python3 python3-pip python3-venv python3-dev pcscd libpcsclite1 \
      libccid pcsc-tools openssl uidmap

Verify the PC/SC stack:

  pcsc_scan

You should see the reader(s) detected. Section 6 stops this host pcscd
before the containers start, because the container pcscd must own the
USB readers.

================================================================================
  3) Install Docker Engine and Docker Compose plugin
================================================================================

Install Docker from the official repository:

  sudo install -m 0755 -d /etc/apt/keyrings
  curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
      sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

  echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
      https://download.docker.com/linux/ubuntu \
      $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
      sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

  sudo apt update
  if ! sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin; then
      echo "docker-ce is not published for this Ubuntu release; using Ubuntu packages"
      sudo rm -f /etc/apt/sources.list.d/docker.list
      sudo apt update
      sudo apt install -y docker.io docker-compose-v2
  fi

Start and enable Docker:

  sudo systemctl enable --now docker

Allow your user to run Docker without sudo:

  sudo usermod -aG docker "$USER"

Log out and back in, then verify:

  docker --version
  docker compose version

The group membership applies only to a new login. In the shell that just
ran usermod, Docker still returns "permission denied" until you reconnect.
To use Docker in that same shell without logging out:

  sudo setfacl -m u:"$USER":rw /var/run/docker.sock

That ACL is lost when the Docker service restarts. The lasting fix is a
new login after usermod.

================================================================================
  4) Clone the project
================================================================================

Choose a directory and clone the repository:

  cd ~
  git clone https://github.com/chuckleu1976/asterisk-docker.git
  cd asterisk-docker

The project files are now in:

  ~/asterisk-docker

================================================================================
  5) Install Python dependencies for the host-side automation script
================================================================================

The host side uses Python to probe SIMs and manage container startup.
Python 3.11 or newer is required (tomllib). Install the PC/SC binding:

  sudo apt install -y python3-pyscard

SIM reads run inside the Asterisk container, so a host pysim virtualenv
is not required. Use the system python3:

  python3 -c "import tomllib; print('python', tomllib.__name__)"

================================================================================
  6) PC/SC and SIM reader setup (customized for your hardware)
================================================================================

This project is designed around a PC/SC stack plus a SIM reader. The Docker
compose setup uses a containerized pcscd service and mounts the reader
configuration directories from this repository.

Choose one of these modes:

- Local USB reader mode (recommended for this guide):
  - The SIM is inserted into a USB smart-card reader attached to the host.
  - Use SIM_MODE=local.
  - The host must expose the USB reader to Docker and pcscd must see it with
    pcsc_scan.

- Remote SIM-server mode:
  - The SIM is served by a remote osmo-remsim bankd server.
  - Set SIM_MODE=remote before generating compose.yaml.
  - Edit the remsim reader configuration so the PC/SC stack points at your
    bankd host and port.

A. Verify the host-side PC/SC stack, then release the readers

Install pcscd and libccid with the packages in section 2. Start it once
to confirm the readers, then stop it. The compose stack runs its own
pcscd and must be the only process holding the USB readers.

  sudo systemctl start pcscd
  pcsc_scan
  sudo systemctl disable --now pcscd

If the reader is not detected, check:

  lsusb
  dmesg | grep -i -E 'ccid|smart|usb'

If your reader is not auto-detected, install the correct driver package and
reload udev rules:

  sudo udevadm control --reload-rules
  sudo udevadm trigger

B. Custom reader configuration for this repository

The project already contains reader configuration under:

  remsim/reader.conf.d/
  remsim/serial/

For local USB readers, no extra reader.conf is usually required; the compose
stack starts pcscd with an empty reader-conf directory so pcscd can auto-detect
USB readers.

For a custom remote reader or a specialized driver, edit:

  nano remsim/reader.conf.d/osmo-remsim-client

Example contents:

  FRIENDLYNAME "osmo-remsim-client"
  DEVICENAME   1:0:192.168.31.68:9998
  LIBPATH      /usr/lib64/pcsc/drivers/serial/libifd_remsim_client.so

Replace the IP/port and library path with the values required by your setup.

C. USB permissions and udev rules

If your reader needs explicit permissions, create a udev rule such as:

  echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="XXXX", ATTR{idProduct}=="YYYY", MODE="0666"' | \
      sudo tee /etc/udev/rules.d/80-ccid.rules > /dev/null

Then reload udev rules:

  sudo udevadm control --reload-rules
  sudo udevadm trigger

D. Make the project use the local reader mode

For the local USB-reader workflow, export or prefix the startup command with:

  export SIM_MODE=local

The compose stack and the bootstrap script will then use the local PC/SC reader
setup instead of the remote osmo-remsim path.

================================================================================
  7) Prepare the working directories and example config
================================================================================

Create the logs directory that the stack expects:

  mkdir -p ../logs/1

Copy the example config to a working instance directory:

  cp -r config/example config/1

If you want to run more than one instance, copy the example config again:

  cp -r config/example config/2
  cp -r config/example config/3

You will now edit the files in config/1 (and optional config/2, config/3, ...).

================================================================================
  7) Configure your SIM readers and IMEIs
================================================================================

Edit the file:

  nano devices.toml

The file maps each reader slot to an Asterisk instance and IMEI.
Example format:

  [[readers]]
  P0= "asterisk1"
  IMEI=359801043400751

  [[readers]]
  P1= "asterisk2"
  IMEI=353295065048026

Replace the values with the actual readers and IMEIs you want to use.
Important:
- P0, P1, P2, ... are reader indexes as seen by PC/SC.
- The IMEI should match the device/modem or the value expected by your carrier
  profile.
- Each reader should have a corresponding instance name such as asterisk1,
  asterisk2, and so on.

================================================================================
  8) Fill in the account and carrier values
================================================================================

Edit the following files and replace the placeholders with your real values:

- config/1/epdg.conf
- config/1/asterisk/pjsip.conf
- config/1/asterisk/extensions.conf
- config/1/ami_usim.ini
- config/1/telegram_token

At minimum you should set:

- your IMSI
- your ICCID
- your MSISDN (phone number)
- your MCC/MNC values
- your carrier domain values
- your SMSC number
- your SIP password
- your Telegram token and chat ID
- the TLS certificate/key for your Asterisk instance

For a self-signed test certificate, generate one like this:

  mkdir -p config/1/asterisk
  openssl req -x509 -newkey rsa:4096 \
      -keyout config/1/asterisk/certificate.key \
      -out config/1/asterisk/certificate.crt \
      -days 3650 -nodes \
      -subj "/CN=asterisk"

If you need a SAN for a specific LAN IP, add it with -addext.

================================================================================
  9) Set your Telegram token
================================================================================

Create the token file:

  echo "YOUR_BOT_TOKEN_HERE" > config/1/telegram_token

If you want notifications, also set the correct chat ID in the dialplan.

================================================================================
  10) Build the images and start the stack
================================================================================

Build from the Dockerfiles in this repository. Do not start the prebuilt
phcodercat/asterisk-vowifi image by itself. That image is only a source
stage inside asterisk/Dockerfile. The image that runs includes the local
ami_usim, entrypoint, and strongSwan tree.

From the repository root, with the SIM cards already inserted:

  chmod +x setup-x86.sh build-images.sh
  ./setup-x86.sh

SIM_MODE=local is the default. The script:

- writes compose.yaml from devices.toml
- runs ./build-images.sh (docker compose build pcscd asterisk)
- probes each reader and starts a container only where a SIM answers

devices.toml maps P0 to asterisk (reader0) and P1 to asterisk2 (reader1).
A host Asterisk process already listens on UDP 5060 and 127.0.0.1:5038,
so the generated ports are:

  reader0  SIP 15060/udp   AMI 127.0.0.1:15038
  reader1  SIP 5062/udp    AMI 127.0.0.1:15039
  reader N AMI 127.0.0.1:(15037+N)

Inside each container, SIP is still 5060 and AMI is still 5038.

The first Asterisk image build compiles Asterisk and strongSwan. Plan on
a long run. Later builds reuse Docker cache.

gitea.osmocom.org answers git clone with an Anubis page, so the Dockerfile
copies the strongSwan tree out of the source image instead of cloning it.

To watch for SIM hotplug after the first start:

  export SIM_MODE=local
  python3 start_sim_container_config.py --watch

================================================================================
  11) Verify the installation
================================================================================

  docker compose ps

Reader0:

  docker compose exec asterisk asterisk -rx "pjsip show registrations"

Reader1, after its container is running:

  docker compose exec asterisk2 asterisk -rx "pjsip show registrations"

Registered means the IMS registration is up. The container health check
also requires the IPsec child SA to be ESTABLISHED.

  docker compose exec asterisk swanctl --list-sas

================================================================================
  12) SMS gateway
================================================================================

The gateway is an AMI client and a web UI. It is not part of ./setup-x86.sh.

Copy the example and set one [[devices]] block per running container.
ami_port must be the host port from compose.yaml (15038 and 15039), not
5038. read_sms_frequency is required even though AMI delivers SMS as
events. recordings_base_dir is the host logs directory (../logs from
this repo).

  cd sms-gateway
  cp config.toml.example config.toml
  # edit iccid, imsi, msisdn, ami_port, and the web password

Build the UI, then the release binary. Node.js 22 and pnpm 9 are enough
for the frontend. Rust/Cargo builds the server. The binary embeds
frontend/dist, so build the UI first.

  # if node is not installed, unpack the official linux-x64 tarball
  # onto PATH, then: corepack enable && corepack prepare pnpm@9.15.4 --activate
  cd frontend && pnpm install && pnpm run build && cd ..
  cargo build --release

Run it as a user service so it does not need root:

  mkdir -p "$HOME/.config/systemd/user" logs data
  cp contrib/systemd/sms-gateway.user.service \
      "$HOME/.config/systemd/user/sms-gateway.service"
  systemctl --user daemon-reload
  systemctl --user enable --now sms-gateway.service

The UI listens on port 8080. From the LAN:

  http://<this-host>:8080

Log lines should show "logged in" for each AMI port. To keep the user
service running after reboot:

  sudo loginctl enable-linger "$USER"

================================================================================
  13) Troubleshooting
================================================================================

If no SIMs are detected:
- stop the host pcscd (the container pcscd must own the readers)
- reseat the card and run ./setup-x86.sh again
- confirm lsusb shows the reader

If Docker says permission denied:
- log in again after usermod -aG docker
- or setfacl the socket as described in section 3

If a container fails to bind 5060 or 5038:
- a host Asterisk is still using those ports
- reader0 must stay on 15060 and 15038
- do not change those back while /usr/sbin/asterisk is running

If the image build fails on an IPv6 address with "network is unreachable":
- this host has no global IPv6 route
- retry the build; Docker will use IPv4 when that route fails over

If registration fails:
- the SIM must be seated before the container starts
- check pjsip show registrations and swanctl --list-sas
- confirm devices.toml IMEI and the values written into config/<N>/

================================================================================
  14) Useful commands
================================================================================

Build only:

  ./build-images.sh

Probe SIMs and start containers:

  export SIM_MODE=local
  python3 start_sim_container_config.py --setup

List readers:

  python3 start_sim_container_config.py --list

Stop the stack:

  docker compose stop

Tear down containers (generated config/1 .. config/8 are left in place):

  docker compose down

================================================================================
  Notes
================================================================================

This stack is for test and evaluation. It is not a production phone system
and may need carrier-specific tuning for your SIM.

Work on the machine's LAN address. A VPN interface on the same host is not
the address you configure or browse to.
